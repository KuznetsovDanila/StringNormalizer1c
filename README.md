# Нормализация строк: очистка и проверка строковых реквизитов для 1С:Предприятие 8

Единая точка очистки и проверки строковых реквизитов объектов 1С: справочников, документов, планов видов характеристик.

Библиотека решает типовую проблему ручного ввода: лишние пробелы, переносы строк, неразрывные пробелы и невидимые символы в наименованиях, артикулах, комментариях. Последствия такого мусора — дубли («Молоко 3,2%» и «Молоко  3,2% » — разные элементы), товар не находится поиском, не сопоставляется при обмене с ЭДО, маркетплейсами, прайсами поставщиков.

Библиотека закрывает вход мусору в момент записи, а не чистит его задним числом обработками.

## Возможности

- Автоматическая очистка строк при записи: крайние и кратные пробелы, табуляция, переносы строк, неразрывные и типографские пробелы, невидимые и управляющие символы
- Многострочные поля: переносы сохраняются, чистится каждая строка
- Проверка смешения кириллицы и латиницы в одном слове (ошибка раскладки)
- Белый список символов для идентификаторов: артикулов, кодов, номеров
- Реквизиты табличных частей, учёт реквизитов групп и элементов
- Настройка полей в модуле менеджера каждого объекта
- Обработка очистки уже накопленных данных с предпросмотром «было / станет»
- Тесты

## Требования

- Платформа **8.3.10** и выше.
- Конфигурация на **БСП** (Библиотеке стандартных подсистем). Используются `ОбщегоНазначения` и `ОбщегоНазначенияКлиентСервер`.

## Установка

1. Загрузите `src/ru` в пустую базу («Конфигурация» → «Загрузить конфигурацию из файлов») и сохраните конфигурацию в `.cf`.
2. В своей конфигурации выполните «Сравнить, объединить с конфигурацией из файла» и перенесите объекты библиотеки. Для типовых конфигураций (ERP, УТ, КА) удобнее перенести их в расширение.
3. Создайте три подписки на события и подключите объекты — см. [Подключение объекта](#подключение-объекта).

Подписки в библиотеку не входят: платформа не допускает подписку без источников, а источники — это объекты вашей конфигурации.

Можно и вручную: скопировать общий модуль и, если нужна, обработку очистки.

## Принципы

1. **Одна точка.** Правило «какая строка правильная» описано в одном модуле и срабатывает при любом способе записи: из формы, копированием, обработкой, HTTP-сервисом. Проверки не размазываются по формам и обработкам.
2. **Однозначный мусор исправляется, подозрительное — нет.** Двойной пробел никогда не несёт смысла, его можно убрать без вопросов. Латинская «С» в кириллическом слове может быть ошибкой раскладки, а может быть частью кода — такое модуль не исправляет, а сообщает пользователю.
3. **Объект сам описывает свои поля.** Какие реквизиты чистить и по какому правилу, объявляет модуль менеджера объекта. Общий модуль не знает о конкретных справочниках и документах.
4. **Неполное подключение видно сразу.** Если объект подписан, но не описал настройки, запись падает с ошибкой, а не проходит молча.

## Что исправляется и что проверяется

### Исправляется автоматически (нормализация)

| Что | Пример | Результат |
|---|---|---|
| Пробелы в начале и в конце | `" Молоко "` | `"Молоко"` |
| Кратные пробелы | `"Молоко  3,2%"` | `"Молоко 3,2%"` |
| Табуляция | `"Молоко<Tab>3,2%"` | `"Молоко 3,2%"` |
| Неразрывный и типографские пробелы (U+00A0, U+2000–U+200A, U+202F, U+205F, U+3000, U+1680) | — | обычный пробел |
| Переносы строк в **однострочном** поле (ПС, ВК, VT, FF, NEL, U+2028, U+2029) | `"Молоко` ↵ `3,2%"` | `"Молоко 3,2%"` |
| Мягкий перенос (U+00AD) | — | удаляется |
| Символы нулевой ширины (U+200B–U+200D, U+2060–U+2064) | — | удаляются |
| Метки направления текста (U+200E, U+200F, U+202A–U+202E) | — | удаляются |
| BOM (U+FEFF) | — | удаляется |
| Управляющие символы (коды 0–31, 127–159) | — | удаляются |

В **многострочном** поле переносы строк сохраняются, но:
- каждая строка текста нормализуется как однострочная;
- подряд идущие пустые строки схлопываются в одну;
- пустые строки в начале и в конце текста удаляются;
- все виды переводов строки приводятся к `Символы.ПС`.

### Проверяется, но не исправляется

| Проверка | Пример | Результат |
|---|---|---|
| Смешение кириллицы и латиницы в одном слове | `"Мoлоко"` (латинская «o») | предупреждение или ошибка — по правилу |
| Белый список символов (только для идентификаторов) | `"АБ#123"` | ошибка: недопустимые символы `"#" (код 35)` |

Словом считается непрерывная последовательность букв и цифр. Слова целиком на латинице (бренды, единицы измерения) не считаются ошибкой.

Предупреждение выводится пользователю, но запись разрешена. Ошибка запрещает запись.

## Правила

Правило — структура, которая описывает, как обрабатывать поле. Есть три готовых правила, любое поле структуры можно изменить.

| Правило | Для чего | Переносы строк | Смешение алфавитов | Белый список |
|---|---|---|---|---|
| `ПравилоТекст()` | наименования, ФИО, адреса | заменяются пробелом | предупреждение | нет |
| `ПравилоМногострочныйТекст()` | комментарии, описания | сохраняются | не проверяется | нет |
| `ПравилоИдентификатор(Спецсимволы, ПробелРазрешен)` | артикулы, коды, номера | заменяются пробелом | **ошибка** | буквы, цифры и `Спецсимволы` |

У `ПравилоИдентификатор` по умолчанию `Спецсимволы = "-_./"`, `ПробелРазрешен = Истина`.

### Поля правила

| Поле | Тип | Назначение |
|---|---|---|
| `Многострочная` | Булево | Переносы строк значимы и сохраняются |
| `ПроверятьСмешениеАлфавитов` | Булево | Искать слова со смешением кириллицы и латиницы |
| `СмешениеАлфавитовОшибка` | Булево | `Истина` — ошибка, `Ложь` — предупреждение |
| `ДопустимыеСпецсимволы` | Строка, Неопределено | Символы, допустимые кроме букв и цифр. `Неопределено` — белый список не проверяется |
| `ПробелРазрешен` | Булево | Допустим ли одиночный пробел при проверке по белому списку |

Пример своего правила — код без пробелов, смешение алфавитов только предупреждение:

```bsl
Правило = НормализацияСтрок.ПравилоИдентификатор("-", Ложь);
Правило.СмешениеАлфавитовОшибка = Ложь;
НормализацияСтрок.ДобавитьРеквизит(Настройки, "КодПоставщика", Правило);
```

## Подключение объекта

### Шаг 0. Один раз на конфигурацию

1. Перенести объекты библиотеки в конфигурацию (см. [Установка](#установка)). Общий модуль `НормализацияСтрок` — с флагом **Сервер**, без «Вызов сервера», «Привилегированный», «Глобальный».
2. Создать подписки на события. Источники заполняются при подключении первого объекта: платформа не сохраняет подписку без источников.

| Подписка | Событие | Источники | Обработчик |
|---|---|---|---|
| `НормализацияСтрокПередЗаписьюОбъекта` | ПередЗаписью | справочники, ПВХ | `НормализацияСтрок.ПередЗаписьюОбъекта` |
| `НормализацияСтрокПередЗаписьюДокумента` | ПередЗаписью | документы | `НормализацияСтрок.ПередЗаписьюДокумента` |
| `НормализацияСтрокОбработкаПроверкиЗаполнения` | ОбработкаПроверкиЗаполнения | все подключаемые объекты | `НормализацияСтрок.ОбработкаПроверкиЗаполнения` |

Документам нужна отдельная подписка `ПередЗаписью`, потому что у их события другая сигнатура (`РежимЗаписи`, `РежимПроведения`).

В типовых конфигурациях (ERP, УТ, КА) модуль и подписки лучше размещать в расширении — тогда они переживают обновления.

Модулю нужна БСП: используются `ОбщегоНазначения.ЕстьРеквизитОбъекта`, `ОбщегоНазначения.СообщитьПользователю`, `ОбщегоНазначения.МенеджерОбъектаПоПолномуИмени`, `ОбщегоНазначения.ЭтоСправочник`, `ОбщегоНазначения.ЭтоПланВидовХарактеристик`, `ОбщегоНазначенияКлиентСервер.ПутьКТабличнойЧасти`.

### Шаг 1. Добавить объект в источники подписок

Объект добавляется в подписку `ПередЗаписью` своего вида (объект или документ) и в подписку `ОбработкаПроверкиЗаполнения`. Состав источников подписок — это и есть список подключённых объектов, отдельного реестра нет.

### Шаг 2. Описать поля в модуле менеджера

В модуле менеджера объекта разместить экспортную процедуру `ПриОпределенииНастроекНормализацииСтрок`:

```bsl
#Область СлужебныйПрограммныйИнтерфейс

// Описывает реквизиты, которые нормализуются и проверяются при записи.
//
// Параметры:
//  Настройки - Структура - передается в НормализацияСтрок.ДобавитьРеквизит
//                          и НормализацияСтрок.ДобавитьВсеСтроковыеРеквизиты.
//
Процедура ПриОпределенииНастроекНормализацииСтрок(Настройки) Экспорт
	
	// Все строковые реквизиты, кроме служебного поля с JSON.
	НормализацияСтрок.ДобавитьВсеСтроковыеРеквизиты(Настройки, "ДанныеДляОбмена");
	
	// Частные правила указываются после общего - они заменяют правило поля.
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "Артикул", НормализацияСтрок.ПравилоИдентификатор());
	
КонецПроцедуры

#КонецОбласти
```

Внутренняя структура `Настройки` — деталь реализации модуля. Заполнять её нужно только через `ДобавитьРеквизит` и `ДобавитьВсеСтроковыеРеквизиты`.

### Как указывать поля

| Путь | Что означает |
|---|---|
| `"Наименование"` | реквизит шапки, включая стандартные |
| `"Товары.Содержание"` | реквизит табличной части `Товары` |

- Повторное добавление поля заменяет его правило. Поэтому частные правила пишутся **после** `ДобавитьВсеСтроковыеРеквизиты`.
- Если поля нет у объекта, оно молча пропускается.
- Для иерархических справочников и ПВХ учитывается использование реквизита: поле «для элемента» не обрабатывается у группы, и наоборот.

### Что добавляет `ДобавитьВсеСтроковыеРеквизиты`

| Реквизит | Правило |
|---|---|
| Стандартный `Наименование` (если есть у объекта) | `ПравилоТекст` |
| Строка ограниченной длины | `ПравилоТекст` |
| Строка неограниченной длины | `ПравилоМногострочныйТекст` |
| Составной тип (строка или ссылка и т.п.) | пропускается |
| Нестроковые реквизиты | пропускаются |

Обходятся реквизиты шапки и всех табличных частей. Код (`Код`) и номер (`Номер`) не добавляются.

**Внимание:** в строках неограниченной длины часто лежат служебные данные — JSON, XML, сериализованные настройки. Такие поля обязательно перечислять в исключениях, иначе нормализация испортит их содержимое (например, уберёт переносы строк из XML).

### Примеры для типовых объектов

Справочник номенклатуры:

```bsl
Процедура ПриОпределенииНастроекНормализацииСтрок(Настройки) Экспорт
	
	НормализацияСтрок.ДобавитьВсеСтроковыеРеквизиты(Настройки);
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "Артикул", НормализацияСтрок.ПравилоИдентификатор());
	
КонецПроцедуры
```

Справочник контрагентов — только наименования:

```bsl
Процедура ПриОпределенииНастроекНормализацииСтрок(Настройки) Экспорт
	
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "Наименование");
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "НаименованиеПолное");
	
КонецПроцедуры
```

Документ — комментарий и строки табличной части:

```bsl
Процедура ПриОпределенииНастроекНормализацииСтрок(Настройки) Экспорт
	
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "Комментарий", НормализацияСтрок.ПравилоМногострочныйТекст());
	НормализацияСтрок.ДобавитьРеквизит(Настройки, "Товары.Содержание");
	
КонецПроцедуры
```

## Как это работает при записи

```
Пользователь нажимает «Записать»
  │
  ├─ ОбработкаПроверкиЗаполнения
  │    └─ для каждого настроенного поля:
  │         нормализовать копию значения → проверить по правилу
  │         ошибки        → сообщение на поле + Отказ = Истина
  │         предупреждения → сообщение на поле, запись продолжается
  │
  └─ ПередЗаписью
       └─ для каждого настроенного поля (шапка и строки табличных частей):
            нормализовать значение и записать в объект, если изменилось
```

Порядок важен: проверка заполнения выполняется **до** `ПередЗаписью`, поэтому проверяется нормализованная копия значения. Пользователь не получит ошибку из-за пробела, который всё равно будет удалён.

Сообщения привязаны к полю формы, для табличных частей — к конкретной ячейке:

```
Поле "Артикул": недопустимые символы: "#" (код 35), "@" (код 64).
Поле "Товары. Содержание, строка 3": в слове "Мoлоко" смешаны кириллица и латиница, проверьте раскладку.
```

### Когда что срабатывает

| Способ записи | Нормализация (`ПередЗаписью`) | Проверка (`ОбработкаПроверкиЗаполнения`) |
|---|---|---|
| Интерактивная запись из формы | да | да |
| `Объект.Записать()` из кода | да | **нет** |
| `Объект.ПроверитьЗаполнение()` из кода | — | да |
| Загрузка через обмен (`ОбменДанными.Загрузка = Истина`) | **нет** | **нет** |
| Дополнительное свойство отключения установлено | нет | нет |

Проверка заполнения не вызывается платформой при программной записи. Если обработка создаёт объекты и должна соблюдать правила идентификаторов, она вызывает `ПроверитьЗаполнение()` перед `Записать()`.

### Отключение для конкретной записи

Для служебных операций (миграции, восстановление из резервной копии) обработку можно отключить через дополнительное свойство объекта:

```bsl
Объект.ДополнительныеСвойства.Вставить(НормализацияСтрок.ИмяСвойстваОтключения(), Истина);
Объект.Записать();
```

Значение свойства не важно — проверяется только его наличие.

## Обмены и загрузки

При `ОбменДанными.Загрузка = Истина` подписки ничего не делают. Это сознательное решение: при обмене за чистоту данных отвечает либо система-источник, либо правила конвертации.

Если нормализация при загрузке нужна, её вызывают явно:

```bsl
// В правилах конвертации, обработке загрузки из Excel и т.п.
НормализацияСтрок.НормализоватьОбъект(Объект);
Объект.ОбменДанными.Загрузка = Истина;
Объект.Записать();
```

`НормализоватьОбъект` использует те же настройки из модуля менеджера, что и подписки, но только исправляет — не проверяет и не запрещает запись.

Для отдельных значений до создания объекта (например, при поиске существующего элемента по артикулу из файла) используется `НормализоватьСтроку`:

```bsl
Артикул = НормализацияСтрок.НормализоватьСтроку(СтрокаФайла.Артикул);
Номенклатура = Справочники.Номенклатура.НайтиПоРеквизиту("Артикул", Артикул);
```

## Очистка существующих данных

Подписки защищают только новые записи. Данные, которые уже лежат в базе, очищаются обработкой **«Очистка незначимых символов в строках»** (`ОчисткаНезначимыхСимволов`).

Порядок работы:

1. **Объекты.** Обработка сама находит подключённые объекты — источники подписок `ПередЗаписью` библиотеки — и показывает их списком. Снимите отметки с тех, которые сейчас чистить не нужно.
2. **Найти.** Поиск ничего не меняет. Для каждого «грязного» поля выводится строка: объект, поле (для табличной части — с номером строки), значение **«Было»** и **«Станет»**. Незначимые символы в них показаны наглядно: крайние и кратные пробелы — `·`, перевод строки — `¶`, прочие — `[код]`, например `[160]` для неразрывного пробела. Двойной щелчок по строке открывает объект.
3. **Очистить отмеченные.** Отмеченные объекты перезаписываются, каждый в своей транзакции с управляемой блокировкой. Ошибка одного объекта не останавливает остальные: результат пишется в колонку «Результат», подробности — в журнал регистрации, событие «Очистка незначимых символов». Успешно очищенные строки снимаются с отметки, строки с ошибками остаются отмеченными для повтора.
4. **Поиск дублей.** После очистки часть элементов станет одинаковой. Запустите типовую обработку БСП «Поиск и удаление дублей» и разберите результат вручную.

Параметры:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| Не более объектов за проход | 5000 | Ограничение поиска. На большой базе очищайте порциями: найти → очистить → найти снова. 0 — без ограничения |
| Записывать в режиме загрузки | выключен | Запись с `ОбменДанными.Загрузка = Истина` |

**Обычная запись** (режим загрузки выключен) выполняет всю логику объекта: проверки, версионирование, регистрацию изменений к обмену — очищенные значения уйдут в другие базы. Документы записываются в режиме `РежимЗаписиДокумента.Запись`, без перепроведения. Объекты, которые не проходят проверки (например, документы в закрытом периоде), не запишутся — это видно в колонке «Результат».

**Режим загрузки** пропускает обработчики объекта, проверки и регистрацию к обмену. Подходит, когда очищенные значения не должны уходить в обмен или старые данные не проходят текущие проверки. Нормализацию в этом режиме обработка выполняет сама через `НормализоватьОбъект`.

Без формы ту же работу можно выполнить из кода:

```bsl
Обработка = Обработки.ОчисткаНезначимыхСимволов.Создать();

ПолныеИмена = Новый Массив;
ПолныеИмена.Добавить("Справочник.Номенклатура");
Найдено = Обработка.НайтиОбъекты(ПолныеИмена, 5000);
// Найдено.Строки - Массив из Структура: ПолноеИмя, Идентификатор, Объект, Поле, Было, Станет.

Объекты = Новый Массив;
Для Каждого НайденнаяСтрока Из Найдено.Строки Цикл
	Объекты.Добавить(Новый Структура("ПолноеИмя, Идентификатор",
		НайденнаяСтрока.ПолноеИмя, НайденнаяСтрока.Идентификатор));
КонецЦикла;
// Объект с несколькими "грязными" полями достаточно передать один раз:
// повторная запись вернет "Изменений не требуется".
Результаты = Обработка.ОчиститьОбъекты(Объекты, Ложь);
```

## Тесты

Обработка **«Тесты»** проверяет строковые функции общего модуля: нормализацию однострочных и многострочных значений, поиск незначимых символов, проверку по правилам и наглядное представление. Тесты не обращаются к данным базы. Откройте обработку и нажмите «Выполнить тесты».

## Справочник программного интерфейса

### Работа со строками

#### `НормализоватьСтроку(Строка, Многострочная = Ложь)` → Строка

Приводит строку к нормальному виду по правилам из раздела «Исправляется автоматически». Значение не строкового типа возвращается без изменений.

| Параметр | Тип | Описание |
|---|---|---|
| `Строка` | Строка | Исходная строка |
| `Многострочная` | Булево | `Истина` — переносы строк значимы и сохраняются |

```bsl
НормализацияСтрок.НормализоватьСтроку("  Молоко" + Символы.ПС + "3,2%  ");  // "Молоко 3,2%"
```

#### `ЕстьНезначимыеСимволы(Строка, Многострочная = Ложь)` → Булево

`Истина`, если строка изменится при нормализации. Для отчётов и поиска «грязных» данных.

#### `ПроверитьСтроку(Строка, Правило)` → Структура

Проверяет **нормализованную** строку по правилу. Возвращает структуру:

| Поле | Тип | Описание |
|---|---|---|
| `Ошибки` | Массив из Строка | Нарушения, запрещающие запись |
| `Предупреждения` | Массив из Строка | Замечания, не запрещающие запись |

```bsl
Артикул = НормализацияСтрок.НормализоватьСтроку(ИсходныйАртикул);
Результат = НормализацияСтрок.ПроверитьСтроку(Артикул, НормализацияСтрок.ПравилоИдентификатор());
Если Результат.Ошибки.Количество() > 0 Тогда
	// ...
КонецЕсли;
```

Тексты сообщений начинаются со строчной буквы — их удобно дополнять префиксом (при записи модуль добавляет `Поле "<представление>": `).

### Правила

#### `ПравилоТекст()` → Структура

Однострочный текст, смешение алфавитов — предупреждение. Описание полей — в разделе [Поля правила](#поля-правила).

#### `ПравилоМногострочныйТекст()` → Структура

Многострочный текст, переносы сохраняются, смешение алфавитов не проверяется.

#### `ПравилоИдентификатор(ДопустимыеСпецсимволы = "-_./", ПробелРазрешен = Истина)` → Структура

Идентификатор: белый список символов, смешение алфавитов — ошибка.

### Настройки объекта

Вызываются только из `ПриОпределенииНастроекНормализацииСтрок` модуля менеджера.

#### `ДобавитьРеквизит(Настройки, Путь, Правило = Неопределено)`

Добавляет поле. Без правила используется `ПравилоТекст()`. Повторный вызов для того же пути заменяет правило.

#### `ДобавитьВсеСтроковыеРеквизиты(Настройки, Исключения = "")`

Добавляет все строковые реквизиты шапки и табличных частей. `Исключения` — пути через запятую, например `"ДанныеДляОбмена, Товары.КлючСвязи"`.

### Работа с объектами

#### `НормализоватьОбъект(Объект)`

Нормализует все настроенные поля объекта, включая табличные части. Для правил конвертации и обработок загрузки. Не проверяет и не меняет `Отказ`.

#### `ИмяСвойстваОтключения()` → Строка

Имя дополнительного свойства, отключающего нормализацию и проверку при записи.

### Сведения

#### `ПодключенныеОбъекты()` → Массив из ОбъектМетаданных

Объекты, подключённые к нормализации: источники подписок `ПередЗаписью` с обработчиками модуля.

#### `НастроенныеПоля(МетаданныеОбъекта)` → Массив из Структура

Поля объекта из его модуля менеджера, которые существуют в метаданных: `ИмяТабличнойЧасти`, `ИмяРеквизита`, `Представление`, `Правило`.

#### `НаглядноеПредставление(Значение)` → Строка

Делает незначимые символы видимыми: крайние и кратные пробелы — `·`, перевод строки — `¶`, прочие — `[код]`. Для отчётов, результат не предназначен для записи.

```bsl
НормализацияСтрок.НаглядноеПредставление(" Молоко  3,2%" + Символ(160));  // "·Молоко··3,2%[160]"
```

### Обработчики подписок

Вызываются только подписками на события, вручную не используются.

| Процедура | Событие |
|---|---|
| `ПередЗаписьюОбъекта(Источник, Отказ)` | ПередЗаписью справочников, ПВХ |
| `ПередЗаписьюДокумента(Источник, Отказ, РежимЗаписи, РежимПроведения)` | ПередЗаписью документов |
| `ОбработкаПроверкиЗаполнения(Источник, Отказ, ПроверяемыеРеквизиты)` | ОбработкаПроверкиЗаполнения |

## Ограничения

- **Наборы записей регистров не обрабатываются**, только ссылочные объекты.
- **Проверка при программной записи не срабатывает** — см. [Когда что срабатывает](#когда-что-срабатывает).
- **Обмены пропускаются** — см. [Обмены и загрузки](#обмены-и-загрузки).
- **Алфавиты:** проверка смешения и белый список знают только базовую латиницу (A–Z), кириллицу (А–я, Ё, ё) и цифры 0–9. Буквы других алфавитов (украинские «і», «ї», казахские, латиница с диакритикой) в идентификаторах считаются недопустимыми. Если это нужно, расширьте функции `ЭтоЛатиница` и `ЭтоКириллица`.
- **Настройки читаются при каждой записи** — вызывается метод менеджера одного записываемого объекта. При тяжёлых настройках (`ДобавитьВсеСтроковыеРеквизиты` на объекте с сотнями реквизитов) результат `ПравилаОбъекта` можно кэшировать в модуле с повторным использованием возвращаемых значений.
- **Форма не обновляется до записи.** Пользователь видит исправленное значение после записи. Если нужно исправлять сразу при вводе, вызовите `НормализоватьСтроку` из обработчика `ПриИзменении` поля (через серверный вызов или вынеся строковые функции в клиент-серверный модуль).

## Вопросы и ответы

**Почему не исправлять смешение алфавитов автоматически?**
Нельзя надёжно определить, какой алфавит «правильный»: в `"AB-123"` латиница может быть настоящей, а в `"Мoлоко"` — ошибкой. Автоисправление здесь означало бы молча менять данные пользователя, в том числе идентификаторы, по которым идёт сопоставление с внешними системами.

**Почему объект, подключённый без метода в модуле менеджера, падает с ошибкой?**
Чтобы неполное подключение обнаружилось при первой же записи на тестовой базе, а не через месяц по жалобе на дубли. Ошибка «Метод объекта не обнаружен» однозначно указывает, что делать.

**Почему не обрабатывать все строковые реквизиты всех объектов автоматически?**
В строках хранятся не только тексты: JSON, XML, ключи, служебные данные. Нормализация их испортит. Поэтому объект явно объявляет свои поля, а `ДобавитьВсеСтроковыеРеквизиты` — осознанный выбор с исключениями.

**Можно ли использовать функции модуля без подключения объекта?**
Да. `НормализоватьСтроку`, `ЕстьНезначимыеСимволы`, `ПроверитьСтроку` и конструкторы правил не зависят от подписок и настроек — их можно вызывать из любой серверной процедуры.
